**Роль:** Ты — Senior Python Developer и Архитектор ПО. Твоя задача — провести глубокий рефакторинг предоставленного монолитного кода приложения на `tkinter` и `matplotlib`. 

**Цель:** Переписать код так, чтобы он стал модульным, легко читаемым, масштабируемым и удобным для дальнейшего сопровождения. Приложение должно сохранить 100% своего текущего функционала.

**Проблемы текущего кода, которые нужно решить:**
1. **God Object:** Класс `ChromatogramApp` перегружен (более 800 строк). UI, бизнес-логика, работа с данными и отрисовка графиков смешаны в одну кучу.
2. **Нарушение PEP 8:** Множество инструкций записаны в одну строку через точку с запятой (например, `a = 1; b = 2; c()`).
3. **Слабая типизация:** Используются обычные словари (`dict`) для хранения сложных структур данных (графики, вспомогательные линии, стили).
4. **Тесная связность (Tight Coupling):** Логика отрисовки Matplotlib напрямую зависит от виджетов Tkinter (например, чтение значений прямо из `Spinbox` внутри метода `refresh_plots`).

**Требования к новой архитектуре (Разделение ответственности / MVC):**
Разбей монолитный файл на логические модули (файлы). Предлагаемая структура:

1. **`models.py` (Модели данных):**
   - Используй `dataclasses` для описания структур данных.
   - Создай классы: `PlotItem` (для хранения данных одного графика), `HelperLine` (для вспомогательных линий), `StyleConfig` (для хранения настроек стиля).

2. **`data_manager.py` (Работа с данными):**
   - Класс или функции для загрузки данных из CSV/TXT (вынос логики `load_data`).
   - Обработка данных (смещение по времени, нормализация).

3. **`plotter.py` (Отрисовка графиков):**
   - Класс `ChromatogramPlotter`, который инкапсулирует работу с `matplotlib` (`Figure`, `Axes`).
   - Он должен принимать данные (модели) и настройки, и только отрисовывать их. Никаких зависимостей от `tkinter` внутри этого класса!

4. **`ui/` (Пакет пользовательского интерфейса):**
   - Раздели UI на компоненты.
   - `main_window.py` — главное окно с графиком.
   - `control_panel.py` — панель управления (Toplevel).
   - Отдельные классы для вкладок: `TabFiles`, `TabScale`, `TabLabels`, `TabHelpers`, `TabStyle`.
   - Использование паттерна Observer (или простых коллбэков) для связи UI с логикой. UI должен только генерировать события (например, "изменился масштаб", "добавлен файл").

5. **`app.py` (Контроллер/Точка входа):**
   - Главный класс приложения, который инициализирует модели, UI и Plotter, и связывает их между собой (назначает коллбэки).

**Требования к качеству кода:**
- Строгое соблюдение **PEP 8** (одна инструкция на строку, правильные отступы, snake_case для переменных и методов, CamelCase для классов).
- Обязательное использование **Type Hints** (аннотаций типов) для всех аргументов функций и возвращаемых значений.
- Добавление **Docstrings** к основным классам и методам.
- Избавление от "магических чисел" и хардкода.
- Безопасная обработка ошибок (try-except) при парсинге пользовательского ввода.

**Формат ответа:**
Поскольку код большой, выдавай ответ по частям (по файлам). 
1. Сначала напиши `models.py` и `data_manager.py`.
2. Затем напиши `plotter.py`.
3. Затем напиши компоненты UI.
4. В конце напиши `app.py`.
